# St. Francis Girls' High School — Suwerwa

Static website (HTML / CSS / JavaScript) with two ways to edit the content.
No build step for the site itself, no server required to view it, no database.
Hosting and both editors are free.

---

## What's here

```
index.html  about.html  academics.html  admissions.html
student-life.html  leadership.html  news.html  gallery.html
contact.html  404.html

assets/css/parts/       styling, split by concern (see below)
assets/js/              scripts, split by concern (see below)
assets/img/             crest, icons, photography

admin/                  content manager (Decap CMS) — needs the live site
dashboard/              offline dashboard — works from a plain folder
data/*.json             content files the content manager writes to

build.py                regenerates the pages from one shared shell
netlify.toml            hosting configuration
robots.txt  sitemap.xml search engine files
preview.bat preview.sh  start a local preview server
```

Every page is generated by `build.py` so the header, footer and `<head>` can
never drift apart. **Edit `build.py`, then run `python3 build.py`** — do not
hand-edit the HTML files, they get overwritten.


### Where to look when something is wrong

Each file does one job, so a fault usually points straight at a file.

**Styling** — `assets/css/parts/`, loaded in numbered order. Each file carries
its own media queries, so a layout problem at one screen size is fixed in the
same file as the layout itself.

| File | Covers |
|---|---|
| `01-tokens.css` | Colours, fonts, spacing scale. Change the brand here. |
| `02-base.css` | Reset, type scale, page widths, skip link, focus rings |
| `03-header.css` | Utility bar, sticky header, navigation, buttons, mobile menu |
| `04-hero.css` | Homepage hero and the year rail beneath it |
| `05-home.css` | Pillars, statistics band, Principal, results teaser, values, voices, news, closing call to action |
| `06-pages.css` | Interior page headers, prose, tables, cards, timeline, gallery, contact |
| `07-footer.css` | Footer and the WhatsApp button |
| `08-states.css` | Scroll reveals, "coming soon" styling, draft bar, print, reduced motion |

**Scripts** — `assets/js/`, loaded in this order:

| File | Covers |
|---|---|
| `content.js` | All school content. Generated — do not hand-edit unless you mean to. |
| `core.js` | Shared helpers and the "run once content is ready" queue |
| `nav.js` | Mobile menu and sticky header. Runs immediately. |
| `motion.js` | Scroll reveals and counting statistics |
| `render.js` | Contact details, Principal, news, voices, gallery, leadership, lists, fees |
| `results.js` | Examination figures, sparkline and grade table |
| `data.js` | Decides which content source to use, then starts everything. **Must load last.** |

If you add a script, put it before `data.js` and wrap the part that needs
content in `SF.ready(function () { ... })`.

The dashboard is split the same way under `dashboard/css/` and `dashboard/js/`.
To add a new editable list, copy a block in `dashboard/js/03-lists.js`.

## Two ways to edit the content

Both produce the same website. Use whichever suits the moment.

### `dashboard/` — the offline dashboard

Works anywhere, including from a folder on a memory stick with no internet.
Open `dashboard/index.html`, edit, and press **Publish changes**. A new
`content.js` downloads; put it into `assets/js`, replacing the old one, and
upload the site.

Best for: building the site, working offline, and any time a server isn't handy.

### `admin/` — the content manager (Decap CMS)

Needs the site to be live on Netlify. The school signs in with an email and
password from any device, edits, and presses Publish. Changes go straight to
the site within about a minute — no files to move.

Best for: handing over to the school once the site is live.

### Which one the site reads

`main.js` prefers `data/*.json` when the site is being served, and falls back to
`content.js` when it isn't. So the content manager wins on the live site, and
the offline dashboard covers everything else.

**Keep them in step.** If the school has been using the content manager, pull
the repository before editing in the offline dashboard, or the older
`content.js` will be the one that ships.

## Brand

Colours are sampled from the school crest, not guessed:

| Token | Hex | Used for |
|---|---|---|
| `--navy` | `#123499` | header, headings, primary buttons |
| `--navy-deep` | `#0A1B4D` | stats band, page headers |
| `--navy-ink` | `#071235` | footer, utility bar |
| `--crimson` | `#CE140C` | small rules only — used sparingly on purpose |
| `--gold` / `--gold-bright` | `#C9922A` / `#EAA918` | numbers, calls to action, accents |
| `--paper` | `#F6F4EF` | page background |

Typefaces: **Fraunces** (headings) and **Public Sans** (body), with Georgia and
the system sans as fallbacks. Change all of it in the `:root` block at the top
of `assets/css/main.css`.

## Viewing it locally

- **Just looking?** Open `index.html`. It works — the site falls back to
  `content.js` and needs no server.
- **Testing the content manager?** It needs a server. Double-click
  `preview.bat` (Windows) or run `bash preview.sh`, then open
  `http://localhost:8000/admin/`. Sign-in will still fail until the site is
  deployed, unless you also run `npx decap-server` in a second terminal —
  `local_backend: true` is already set for that.

## Deploying (free)

1. Push this folder to a GitHub repository.
2. At netlify.com choose **Add new site → Import an existing project** and pick
   the repository.
3. Build command: leave empty. Publish directory: `.`
4. The site goes live at a `*.netlify.app` address.

### Turning on the content manager

5. **Site configuration → Identity → Enable Identity**
6. Under **Registration**, set **Invite only**. This matters — leaving it open
   would let anyone register.
7. Under **Services**, enable **Git Gateway**.
8. **Identity → Invite users** and enter the school's email address.
9. They accept the invitation, set a password, and sign in at
   `your-site.netlify.app/admin/`.

### Adding the school's own domain

Netlify → Domain management → Add a domain. A `.sc.ke` or `.ac.ke` domain is
registered through a KENIC-accredited registrar and costs roughly KES 1,000–1,500
a year.

## Before going live

- [ ] Replace `assets/img/hero.jpg` and all `pillar-*`, `page-*`, `gallery-*`
      and `cta.jpg` files with real photographs of the school (same filenames)
- [ ] Add the Principal's message and portrait
- [ ] Add telephone, WhatsApp and email — several pages show placeholders until
      these exist, and the floating WhatsApp button stays hidden without a number
- [ ] Add the fee structure and Grade 10 requirements
- [ ] **Confirm which senior school pathways the school is approved to offer**
      (STEM, Social Sciences, Arts and Sports Science) and the subject
      combinations — a school may offer at most two
- [ ] Confirm the 2013 mean and the entry totals for 2019, 2021 and 2022 against
      the school's own board before publishing the results page
- [ ] Add the 2025 K.C.S.E. results
- [ ] Update `SITE` in `build.py`, `robots.txt` and `sitemap.xml` once the real
      domain is known, then rerun `python3 build.py`
- [ ] Submit the sitemap in Google Search Console and create a Google Business
      Profile — this is where most of the local search traffic will come from

## Notes on the build

- **Mobile first.** Most visitors will be on a phone, often on mobile data. The
  homepage carries one hero image and no video; first load is well under 100 KB
  before photographs.
- **Works without JavaScript.** Every page reads correctly with scripts
  disabled; JavaScript only adds the menu, reveals, counters and live content.
- **Accessibility.** Skip link, visible keyboard focus, semantic landmarks,
  labelled controls, and `prefers-reduced-motion` respected throughout.
- **Print stylesheet** included — the fee structure and results table print
  cleanly, which parents do.
- **Curriculum.** The site is written for the Competency-Based Curriculum:
  admission is to Grade 10 of senior school through Ministry placement, not
  Form One. The K.C.S.E. record stays published because the school still has
  Form Four candidates until the final national K.C.S.E. in 2027; Grade 12
  results can be added to the same table afterwards.
- **K.C.S.E. mean grades round to the nearest grade point**, matching the
  school's own board across all twelve years on record. The offline dashboard
  works this out automatically and warns when the grade counts don't add up to
  the number of candidates entered.
